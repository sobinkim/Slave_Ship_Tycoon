# 보호 효과·방패·아이콘

방어 효과는 함선 Role을 보고 자동으로 붙지 않습니다. **Provider(제공자) → 효과 데이터 → Receiver(수신자)**를 연결해야 합니다. 방패 그림과 피해/타겟 판정도 별도 역할입니다.

## 현재 후열 보호 규칙

ImmediateRearProtection은 같은 행의 바로 뒤 한 칸을 보호합니다. Require Front Line이 켜지면 전열의 공급 함선만 제공할 수 있습니다.

- 아군: 전열 공급함 (열 2, 같은 행)에서 바로 뒤 중열 (열 1, 같은 행) 보호.
- 적: 전열 공급함 (열 0, 같은 행)에서 바로 뒤 중열 (열 1, 같은 행) 보호.
- 뒤 칸이 비어 있으면 다음 칸이나 다른 행을 찾지 않습니다.
- 보호 대상은 일반 직접 타겟 후보에서 제외됩니다.
- Protected Damage Multiplier=0.7이면 피해 30% 감소입니다. 0.3을 넣으면 감소 30%가 아니라 받는 피해 30%입니다.

습격함의 Can Target Protected Ships는 타겟 후보 포함 옵션입니다. 켜도 피해 감소는 적용됩니다.

## 구조

| 구성 | 역할 |
|---|---|
| FleetEffectDefinition | 공유 규칙·아이콘·수치 |
| ImmediateRearProtection | 바로 뒤 대상 선택 |
| FleetEffectProvider | 전투의 아군 목록에 효과 제공/회수 |
| FleetEffectReceiver | 공급원별 수신 상태·피해 배율·보호 판정 |
| FleetEffectVisual/ShipShieldVisual | 방패 표시·피격 반응 |
| FleetEffectStatusIcons | 실제 받은 효과의 아이콘 |
| ShieldBreakEffect | 사망 때 독립된 파편 연출 |

## 보호 함선 제작

1. IroncladDefender를 복제합니다.
2. FleetEffectProvider의 Owner, Source Receiver, Effects를 확인합니다.
3. Effects에 `Assets/SB/Data/FleetEffects/ImmediateRearProtection.asset`을 연결합니다.
4. 받을 함선의 FleetEffectReceiver와 Presentations의 효과/시각 연결도 확인합니다.
5. 전열에 공급 함선, 바로 뒤 칸에 수신 함선을 배치합니다.
6. 보호 대상 선택 제한과 피해 감소를 확인합니다.

새 방어함만 다른 감소율을 원하면 효과 에셋을 복제해서 연결합니다. 공용 효과 에셋을 바꾸면 그것을 참조하는 다른 방어함도 같이 바뀝니다. 복제한 효과의 시각 연결도 새 효과 참조와 맞춰야 합니다.

## 방패 모양과 아이콘

방패 기준 Transform은 보통 `Presentation/ShieldAnchor`입니다. Local Position/Rotation/Scale로 위치·각도·크기를 맞춥니다. ShipShieldVisual의 Source Color, Protected Color, Pulse Seconds/Amount, Hit Flash Seconds로 투명도·맥동·피격 강조를 조절합니다.

효과 에셋의 Status Icon/Status Icon Color가 아이콘을 결정합니다. 수신 함선의 `WorldUI/HullCondition/StatusIcons`에서 위치를, FleetEffectStatusIcons의 Icon Size/Icon Spacing에서 크기·간격을 조절합니다. Receiver/Icon Template을 명시적으로 연결하세요.

공급자의 파란 방패가 보인다고 수신 효과 아이콘도 자동으로 생기는 것은 아닙니다. 아이콘은 실제로 효과를 받은 함선에 표시됩니다. 같은 효과를 여러 공급원에서 받아도 아이콘은 한 개이며 마지막 공급원이 사라질 때 제거됩니다.

## 해제와 재사용

공급 함선 사망 때 보호 판정은 즉시 끝납니다. 전투 종료·비활성·풀 반환 때도 효과를 정리합니다. 일반 회수는 파괴 연출 없이 정리하고 사망 해제는 방패 파편 연출을 사용할 수 있습니다.

현재 배치는 전투 중 고정입니다. 향후 이동·실시간 재편성 기능을 구현하면 배치 변경 후 Provider.BindBattle 등으로 대상을 명시적으로 다시 계산해야 합니다.

## 확인 목록

전열/후열 교체, 빈 뒤 칸, 다른 행, 공급자 사망, 두 공급자 중 하나 제거, 전투 종료, 다음 출항을 각각 봅니다. 모양만 보고 판정 성공으로 판단하지 말고 실제 타겟 선택·피해량도 확인하세요.
