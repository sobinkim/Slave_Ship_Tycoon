# 화물·시세·판매 정산

## 세 시스템의 역할

CargoManager는 화물 수량과 무게를, MarketPriceManager는 운송 중 판매 배율을, SalesManager는 판매 진입 때의 화물을 기준으로 최종 보상을 계산합니다. 화면의 궤짝·아이콘·용량 막대는 이 데이터를 표시하는 역할입니다.

## 화물 설정

`Assets/SB/SO/TransportItemSOs/GoldBox.asset`, `ShipElementBox.asset`을 선택합니다.

| TransportItemSO 필드 | 의미 |
|---|---|
| Icon | 화물 UI 그림 |
| Type | Gold 또는 ShipElement 구분 |
| Rewards | 화물 1개 판매의 재화 종류·기본 수량 |
| Base Weight | 화물 1개가 차지하는 적재 무게 |

씬 CargoManager의 Cargo Data에는 Item과 Amount가 들어갑니다. 최대 용량은 UpgradeEvent의 Cargo Capacity를 받아 사용하므로 Inspector의 실행 중 용량만 바꾸는 것으로 영구 밸런스를 설정하지 마세요. [12번 강화](12_강화와_자연회복.md)에서 초기 Cargo Capacity를 함께 조절합니다.

무게 합계는 `Amount × BaseWeight`의 합입니다. LoadCargo는 한 개의 추가 무게가 남은 용량 이내일 때 수량을 1 증가시키고 이벤트를 보냅니다. UnloadCargo는 한 개 감소, ClearCargo는 모두 비우는 메서드입니다.

예: 최대 15, 금화 상자 무게 1, 재료 상자 무게 2라면 금화 5개+재료 5개가 총 15입니다. 이는 예시이며 실제 에셋의 BaseWeight와 강화값을 확인하세요.

## UI 연결과 사용

화물 화면의 CagoController, CagoButtonView, CargoManager 참조와 각 버튼 Type을 확인합니다. `Cago` 철자는 현재 파일명에 사용되므로 검색할 때 그대로 사용하세요. HoldRepeatButton은 누르는 즉시 한 번 실행하고 Repeat Start Delay 뒤 Repeat Interval 간격으로 반복합니다. 버튼에서 손을 떼거나 영역을 벗어나거나 비활성화되면 중단합니다.

ItemBarManager/ItemBarView/ItemElementView는 수량·아이콘·시세를 표시합니다. CurrentCagoSliderView는 적재 상태 표시입니다. 실제 적재 규칙을 UI 막대 크기로 변경하지 않습니다.

## 운송 시세

SellChapterStartedEvent에서 적재된 종류별 누적 배율을 1로 시작합니다. 운송 구간 클리어마다 기본 시세 1~9를 뽑고 운에 따른 보너스 판정을 합니다. 보너스가 있으면 추가 배율도 1~9에서 뽑습니다. 누적은 이전 값에 `이번 구간 배율 - 1`을 더하는 방식입니다.

예: 누적 1에서 이번 구간 배율 4면 누적 4, 다음 구간 배율 3이면 누적 6입니다. 앞선 누적 값에 매번 곱하는 방식은 아닙니다.

Sell Failure Penalty Percent는 운송 실패 때 누적 상승분에 대한 손실률입니다. 같은 스테이지의 반복 실패는 한 번만 적용하도록 기록합니다. 기본 배율 1까지 모두 비율로 깎는다고 이해하지 마세요. 운의 보너스 확률 계산은 MarketPriceManager.GetBonusChance에 있으므로 회피 확률 에셋과 구분합니다.

## 판매 정산

Sell 진입 때 SalesManager가 화물 수량을 복사해 저장합니다. 이 복사본을 스냅샷이라고 합니다. 운송 중 화면상의 현재 화물을 바꿔도 출발 기준 판매 수량을 그대로 사용합니다.

기본 계산은 `화물 수량 × 1개당 재화 보상 × 적용 누적 배율`입니다. 같은 재화끼리 합산한 뒤 운송 장비 스냅샷의 보정을 적용하고 CurrencyAddRequestEvent로 지급합니다. SaleSettlementCompletedEvent는 결과 화면에 계산 결과를 전달합니다.

정산 화면의 숫자 카운트 연출이 보상을 지급하는 것은 아닙니다. Replay Last Settlement는 표시 재생을 위한 동작이며 다시 지급하는 흐름과 혼동하지 마세요.

## 새로운 화물 종류 추가

기존 두 종류의 보상·아이콘·무게 변경은 에셋 설정으로 가능합니다. 세 번째 종류는 ETransportItemType enum, CargoManager 데이터, 버튼, 화물 UI, 시세/정산 경로, 궤짝 표시 집계 등 연결을 확장해야 합니다. 에셋 하나만 Duplicate해서 자동으로 새 종류가 되는 구조는 아닙니다.

## 확인하기

혼합 적재 → 용량 초과 거절 → 하역 → Sell 진입 → 구간 클리어 시 배율 갱신 → 실패 페널티 → 마지막 구간 정산 → 실제 재화 증가를 확인합니다. 판매 후 화물 비우기 흐름은 CagoController 등 이벤트 수신부까지 함께 보세요.

정산이 없으면 출발 시 화물 수량, MarketPriceManager 연결/이벤트, SellChapterCompletedEvent, 장비 관리자, 재화 수신자를 확인합니다.
