# 웨이브와 챕터 양산

## 데이터 연결을 먼저 이해하기

```text
씬 GameFlowManager / StageSpawnManager
  → ChapterDatabase
     → ChapterContainer (한 챕터)
        ├─ Stages[] → StageEnemyLayout → Enemy 프리팹 12칸
        └─ Boss Layout → 보스용 StageEnemyLayout
```

`StageEnemyLayoutDatabase.asset`도 남아 있지만 현재 GameFlowManager·StageSpawnManager와 Layout Editor는 **ChapterDatabase** 경로를 사용합니다. 이전 데이터베이스에만 등록하면 현재 전투에 반영되지 않습니다.

## 웨이브 제작: Layout Editor 사용

1. 재생을 종료하고 `SB > Stage Enemies > Layout Editor`를 엽니다.
2. Database가 실제 씬에서 사용하는 ChapterDatabase인지 확인합니다.
3. 수정할 Chapter/Stage를 입력하고 **Load**를 누릅니다. 번호만 바꾸면 현재 편집 칸이 자동으로 다른 웨이브로 교체되는 것은 아닙니다.
4. 12칸에 Enemy 프리팹을 드래그합니다. None인 칸은 생성하지 않습니다.
5. **Save Stage Layout**을 누릅니다.
6. 생성·수정된 Layout과 ChapterContainer를 Project 창에서 확인합니다.

저장은 `Assets/SB/Data/StageEnemies/Layouts/Chapter_XX/Stage_XX_YY.asset` 경로를 사용합니다. 해당 파일이 이미 있으면 새 파일 대신 기존 파일을 갱신합니다. 저장 도구는 ChapterContainer를 생성/찾고 ChapterDatabase와 Stages에 연결합니다.

**Create 3 Test Enemies / Create Test Content는 실제 콘텐츠 양산 버튼이 아닙니다.** 테스트용 데이터 생성 도구이므로 커스텀한 게임에 무심코 재실행하지 마세요.

## 기존 편성을 바탕으로 여러 웨이브 만들기

방법 A: 기존 번호를 Load → 새 Stage 번호 입력 → 칸 수정 → Save. 새 번호 입력 후 Load를 누르면 새 번호의 데이터를 읽으므로 기존 복사 구성이 사라질 수 있습니다. 새 번호로 저장하기 전 현재 12칸을 확인하세요.

방법 B: Project 창에서 Layout 에셋 Duplicate → Chapter/Stage 값 수정 → ChapterContainer의 Stages에 직접 등록. 이 방식은 파일 이름과 내부 번호를 모두 제작자가 맞춰야 합니다.

예를 들어 2챕터의 1~3구간을 만들 때 Stages의 Element 0/1/2에 Stage_02_01/02/03을 순서대로 넣습니다. **Element 0이 1스테이지**입니다. 이름만 Stage_02_03으로 바꿔도 내부 Stage 값은 바뀌지 않습니다.

## Obtain과 Sell의 배열 사용 차이

| 항목 | Obtain | Sell |
|---|---|---|
| 일반 전투 | Stages에서 랜덤 웨이브 | Stages를 1번부터 순서대로 |
| 일반 승리 | 다시 웨이브 선택 | 다음 배열 항목 진행 |
| 챕터 종료 | 별도 보스전 승리 | Stages 마지막 구간 승리 |
| Boss Layout | 도전할 보스 데이터 | 현재 보스 도전 경로는 Obtain 전용 |

Obtain에서 선택된 웨이브의 Stage 번호로 스폰 경로를 다시 조회합니다. 그러므로 Stages의 `stage-1` 위치와 Layout.Stage를 일치시키세요. 순서를 섞으면 선택한 웨이브와 실제 스폰 구성이 달라질 수 있습니다.

Sell은 Stages 길이가 MaxStage가 됩니다. 중간 None, 맨 끝 None, 잘못된 번호는 진행 오류의 원인이 됩니다. 연속된 구간을 빠짐없이 등록하세요. 일반 웨이브를 늘리면 운송 기간·시세 누적·난이도도 함께 바뀝니다.

## 새 챕터 만들기

1. `Create > SB > Stage > Chapter Container`로 생성하거나 기존 챕터를 복제합니다.
2. Chapter를 새로운 번호로 변경합니다. 같은 번호를 여러 컨테이너에 넣지 않습니다.
3. Route Type(Obtain/Sell), Enemy Faction(Pirate/Navy)을 확인합니다. Faction을 바꿔도 슬롯의 Enemy 프리팹이 자동 교체되지는 않습니다.
4. Stages에 해당 챕터 Layout을 순서대로 넣습니다.
5. Obtain이면 Boss Layout도 연결합니다.
6. ChapterDatabase의 Chapters에 등록합니다.
7. RewardManager에도 해당 챕터의 ChapterRewardTable을 연결합니다.
8. 이전 챕터 완료 후 새 챕터 진입과 종료를 확인합니다.

예: 5챕터=Obtain이라면 5-1~5-3 일반 웨이브와 별도 보스 Layout을 준비합니다. 이어지는 6챕터=Sell의 6-1~6-5를 등록하면 운송이 5구간으로 진행됩니다. 번호 자체가 경로를 강제하는 것은 아니므로 Route Type을 확인하세요.

## 보스 Layout 별도 제작

Layout 에셋을 복제해 보스용 이름을 붙이고 슬롯에 TestBoss 또는 새 보스를 넣습니다. ChapterContainer의 Boss Layout에 드래그하고 일반 Stages에는 넣지 않습니다. 보스 호출 때 게임 진행의 Stage는 0이지만, 보스 에셋의 Stage 필드를 0으로 설정하는 방식은 아닙니다. 보스는 Boss Layout 참조로 찾습니다.

## 양산 후 확인 목록

- Chapter/Stage 내부 번호와 배열 위치 일치.
- Stages에 None 없음, Obtain의 보스가 일반 목록에 섞이지 않음.
- 적 최소 1척. Layout Editor는 빈 웨이브 저장을 거절합니다.
- 사용 칸마다 고유한 Spawn Point 연결.
- 챕터 번호에 맞는 보상 테이블.
- 새 챕터의 마지막 구간·보스 승리 후 다음 챕터/정산 확인.

아직 다음 챕터 데이터가 없으면 GameFlowManager는 데이터를 찾지 못했다는 로그를 남기고 루프를 멈춥니다. 무한히 다음 챕터를 만들어 주는 기능은 없습니다.
