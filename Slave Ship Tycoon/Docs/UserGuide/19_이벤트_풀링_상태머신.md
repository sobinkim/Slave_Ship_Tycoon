# 이벤트·풀링·상태머신

이 문서는 코드를 수정하려는 사람이 공통 흐름을 이해하기 위한 안내입니다. 콘텐츠 수치만 변경할 때는 각 기능의 Inspector 안내를 먼저 사용하세요.

## Entity와 컴포넌트

Entity.Awake는 자식의 IEntityComponent를 모아 Initialize를 호출하고, IAfterInitialize를 구현한 컴포넌트의 후처리를 실행합니다. EntityComponent는 Owner를 가지고 GetCompo로 같은 Entity의 기능을 조회합니다.

Ship은 이 기반 위에서 ShipStatCompo, EntityHealth, EntityAnimator, 공격 컴포넌트, 효과 수신자 등을 사용합니다. 같은 타입을 여러 개 붙여도 모든 인스턴스를 관리하는 목록으로 처리하지 않으므로 역할마다 기존 구조를 확인하세요. 새로운 컴포넌트를 실행 중에 붙이는 경우 Awake 초기화 이후 캐시에 자동 반영된다고 가정하지 않습니다.

## 상태머신

ShipStateMachine에는 Idle/Move/Attack/Dead 상태가 있습니다. Ship.ChangeState는 상태 전환의 명시적인 진입점입니다. 각 Ship*State가 애니메이션·공격 시작/정리를 맡고 공통 StateMachine/IState가 현재 상태를 관리합니다.

애니메이션 이벤트는 EntityAnimatorTrigger의 AttackStart/AttackEnd/Dead/AnimationEnd 메서드로 전달됩니다. Animator 상태와 게임 상태를 둘 다 확인해야 합니다. 그림의 Renderer.enabled를 바꾸는 것으로 IsDead나 전투 종료가 바뀌지는 않습니다.

## 이벤트 버스

`Bus<TEvent>.Raise`는 같은 타입의 OnEvent 구독자에게 정보를 전달합니다. 이벤트 정의는 `Assets/SB/Scripts/Events`와 공통 EventBus에 있습니다. 예:

| 이벤트 | 흐름 |
|---|---|
| StageStartedEvent | 게임 진행 → 스폰/챕터 정보/보상 준비 |
| StageBattleInitializedEvent | 참가자 생성 → 전투 전 설정 |
| BattleStartEvent | 조우 완료 → 공격/스킬 시작 |
| StageBattleEndedEvent | 승패 → 다음 진행/정리 |
| UpgradeEvent | 강화 → 본선/화물/표시 갱신 |
| ChangedCurrentCargoCapacityEvent | 화물 → 궤짝/용량/판매/화면 |
| CurrencyAddRequestEvent | 정산 등 → 실제 재화 추가 |

새 구독은 구독/해제 위치를 쌍으로 유지하세요. OnEnable에서 등록했다면 OnDisable에서 해제하는 방식이 일반적입니다. 기존 코드 중 Awake 등록 흐름은 그대로 읽고, 새 기능에서 무심코 같은 등록을 중복하지 마세요. 이벤트 이름만 보고 호출 순서를 추정하지 말고 Raise 지점을 확인합니다.

## 풀링

PoolingManager는 프리팹별 대기 큐를 만들고 Get으로 오브젝트를 꺼내거나 새로 만들며 Release로 돌려놓습니다. IPoolable의 OnSpawnedFromPool/OnDespawnedToPool이 재사용 초기화 지점입니다.

Preload Prefabs의 Prefab/Preload Count는 미리 준비할 수량입니다. 등록하지 않은 프리팹도 첫 Get에서 풀을 만들므로 양산한 프리팹을 반드시 미리 등록해야만 생성되는 것은 아닙니다. 다만 전투 스폰에는 씬 PoolingManager 자체가 필요합니다.

SetActive(false)만 호출하면 정상 Release 경로와 다릅니다. 실제 풀 반환은 PoolingManager.Release를 사용합니다. 반환을 두 번 호출하거나 이미 반환한 탄에 늦은 콜백이 실행되지 않도록 기존 수명주기를 따라야 합니다.

## 이전 출항 상태를 막는 장치

Ship.SpawnGeneration은 재생성 세대를 구분합니다. 공격/탄/패배 연출은 이전 타겟 참조가 같은 오브젝트의 새 출항을 가리키는 상황을 구분해야 합니다. 타겟 제거, 버프 제거, 코팅 진행도, 경로 선, MISS/위험 수, 방패 상태도 반환 때 정리합니다.

## 새 기능 추가 기준

입력/상태 주인은 Manager, 설정 주인은 명확한 필드/에셋, 시각 표현은 View/효과 컴포넌트로 나눕니다. 새 전역 매니저나 자동 검색을 먼저 만들기보다 기존 이벤트·명시적 참조를 재사용하세요. 테스트는 생성→실행→정리→같은 인스턴스 재사용까지 포함하는 것이 좋습니다.
