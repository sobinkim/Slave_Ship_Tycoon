# 스폰 위치와 함선 정렬

“누가 나오나”, “어디에 나오나”, “누가 먼저 그려지나”는 서로 다른 설정입니다.

| 원하는 변경 | 설정 위치 |
|---|---|
| 해당 웨이브의 적 종류·수 | StageEnemyLayout.Enemy Slots |
| 함선 사이 거리·엇갈림 | 씬의 Spawn Point Transform |
| 전열/중열/후열이라는 논리 위치 | 슬롯 배열 인덱스 |
| 함선 그림 크기 | 프리팹 Visual.Local Scale |
| 그림 겹침 순서 | SpriteRenderer/SortingGroup, 효과의 Sorting 설정 |

## 적: 3열 × 4행

아래는 **슬롯과 배열의 대응**입니다. 각 행이 화면 위→아래로 보이는지는 Spawn Point의 Y를 어떻게 배치했는지에 달려 있습니다.

| 행 | 전열(열 0) | 중열(열 1) | 후열(열 2) |
|---|---|---|---|
| 1 | Slot 1 / Element 0 | Slot 2 / Element 1 | Slot 3 / Element 2 |
| 2 | Slot 4 / Element 3 | Slot 5 / Element 4 | Slot 6 / Element 5 |
| 3 | Slot 7 / Element 6 | Slot 8 / Element 7 | Slot 9 / Element 8 |
| 4 | Slot 10 / Element 9 | Slot 11 / Element 10 | Slot 12 / Element 11 |

StageSpawnManager는 칸 번호로 `SpawnSlot=(index % 3, index / 3)`을 지정합니다. Slot 8은 (1,2), 즉 세 번째 행의 중열입니다. Transform 이름·거리만 보고 전열을 추론하지 않습니다.

### 현재 씬에서 확인한 적 스폰점

2026-10-02 실행 중 씬에서 읽은 값입니다. 부모는 모두 EnemySpawnPoints이며 Z=0입니다. 아래는 현재 로컬 배치를 이해하는 참고이고, 수정한 씬의 Inspector가 항상 기준입니다.

| 행 | 전열 Point / X,Y | 중열 Point / X,Y | 후열 Point / X,Y |
|---|---|---|---|
| 1 | Point(0,0) / -0.08, 0.04 | Point(1,0) / 0.69, 0.04 | Point(2,0) / 1.42, 0.04 |
| 2 | Point(0,1) / -0.08, -0.60 | Point(1,1) / 0.69, -0.60 | Point(2,1) / 1.42, -0.60 |
| 3 | Point(0,2) / -0.08, -1.24 | Point(1,2) / 0.69, -1.24 | Point(2,2) / 1.42, -1.24 |
| 4 | Point(0,3) / -0.08, -1.88 | Point(1,3) / 0.69, -1.88 | Point(2,3) / 1.42, -1.91 |

아군 부모 EscortShipSpawnPoints 아래에도 Point(0,0) 등의 같은 이름이 있습니다. 이름만 보고 드래그하지 말고 **부모와 배열 연결**을 함께 확인하세요.

## 위치를 조절하는 순서

1. 재생을 종료합니다.
2. 씬 StageSpawnManager의 **Spawn Points** 배열을 펼칩니다.
3. 변경할 Element에 연결된 Transform을 클릭해 실제 오브젝트를 찾습니다.
4. Scene 창의 Gizmos를 켜고 점/슬롯 라벨을 확인합니다.
5. 해당 Point의 **Local Position** X/Y를 조절합니다. 적 함대 부모는 조우 연출 중 이동하므로 자식의 로컬 배치를 기준으로 작업합니다.
6. 같은 열의 X, 같은 행의 Y를 맞추면 격자 대형이 됩니다. 일부 점만 조금 옮기면 엇갈린 대형이 됩니다.
7. 각 Element가 서로 다른 Point인지 확인하고 씬을 저장합니다.
8. 실제 전투에서 큰 함선·보스·체력바 겹침을 봅니다.

Transform 하나를 배열 여러 칸에 재사용하지 마세요. 사용 중인 칸의 중복 참조는 ValidateLayout에서 오류로 처리합니다. 반대로 서로 다른 Transform이어도 좌표가 같으면 시각적으로 겹칠 수 있습니다.

## 배치 예시

다음은 실제 저장값이 아닌 제작 예시입니다. 부모 EnemySpawnPoints의 로컬 공간에서 전열 X=0, 중열 X=0.9, 후열 X=1.8로 정하고 행 Y=0.9, 0.3, -0.3, -0.9로 둡니다. 그러면 12개 지점이 일정 간격으로 배치됩니다. 화면을 보고 함선 폭·체력바 높이에 맞춰 간격을 조절하세요.

전열을 화면 뒤쪽으로 옮겨도 코드상 전열 의미는 유지됩니다. 보호 효과·타겟 규칙과 눈에 보이는 대형을 일치시키려면 배열 의미에 맞춰 점을 배치해야 합니다.

## 아군: 3열 × 3행, 호위선 8척 + 본함

본함은 후열 중앙 `(열 0, 행 1)`에 고정됩니다. 호위선 8칸은 아래와 같이 배치됩니다. 표의 슬롯 번호는 PlayerFleetLoadout 배열 기준이며 Element는 0부터 시작합니다.

| 행 | 후열(열 0) | 중열(열 1) | 전열(열 2) |
|---|---|---|---|
| 1 | Slot 7 / Element 6 | Slot 1 / Element 0 | Slot 2 / Element 1 |
| 2 | 본함 | Slot 3 / Element 2 | Slot 4 / Element 3 |
| 3 | Slot 8 / Element 7 | Slot 5 / Element 4 | Slot 6 / Element 5 |

StageSpawnManager의 **Escort Ship Spawn Points** 배열은 8개입니다. Element 0~5는 중열·전열의 세 행이고 Element 6~7은 본함 위·아래 후열입니다. 본함은 **Main Ship Spawn Point**에서 생성되며 논리 SpawnSlot은 `(0,1)`입니다.

아군 전열은 열 2, 중열은 열 1, 후열은 열 0입니다. 적 전열은 열 0, 중열은 열 1, 후열은 열 2입니다. 열 인덱스가 양 팀에서 반대이므로 보호 효과와 타겟 규칙은 진영별 방향을 확인하세요. 현재 철갑 방어함의 바로 뒤 보호는 아군 전열 공급함 `2→1`, 적 전열 공급함 `0→1`입니다.

## 조우 위치와 도착 위치

StageEncounterDirector의 Enemy Fleet Root가 적 스폰 지점들의 부모이고, Enemy Fleet Root Destination이 접근 완료 지점입니다. Move Speed를 바꾸면 접근 속도가 바뀝니다. **대형 간격은 자식 Point**, **함대 전체의 접근/정지 위치는 부모와 Destination**에서 조절합니다.

### 흩어진 진입과 대형 집결

적은 각 Point의 최종 전투 위치에서 임시 오프셋을 더한 상태로 등장합니다. 접근 후반에는 배마다 서로 다른 지연·시간으로 원래 위치에 모이고, 함대 부모의 접근과 모든 배의 집결이 끝나면 전투가 시작됩니다. 먼저 도착한 배의 이동 물살은 먼저 멈춥니다.

SampleScene의 StageEncounterDirector에서 다음 값을 조절합니다.

| Inspector 항목 | 현재 값 | 역할 |
|---|---|---|
| Move Speed | 1.2 | 함대 부모의 접근 속도 |
| Scatter Offset X Range | 0.10~1.05 | 최종 슬롯보다 뒤쪽(+X)에서 시작하는 거리 |
| Scatter Offset Y | 0.22 | 위아래 출발 위치의 최대 차이(±) |
| Regroup Start Distance | 0.85 | 목적지까지 남은 X 거리가 이 값 이하일 때 집결 시작 |
| Regroup Duration Range | 0.9~1.25초 | 각 배가 자기 자리로 모이는 시간 |
| Max Regroup Delay | 0.25초 | 배마다 집결을 늦게 시작하는 최대 시간 |

임시 위치만 움직이며 Point Transform과 논리적인 SpawnSlot은 바뀌지 않습니다. 따라서 전열 보호와 타겟 규칙은 기존 슬롯을 사용합니다. 산개 폭을 크게 늘리면 선체·체력바가 겹치거나 화면 밖으로 나갈 수 있으므로 실제 화면에서 맞춥니다. Destination은 기존과 같이 **X 좌표만** 사용합니다.

진입을 취소하거나 적을 풀에 반환할 때는 StageEncounterDirector.CancelEncounterSequence로 이동 상태와 임시 위치를 정리합니다. 풀에서 다시 나온 함선은 SpawnGeneration을 비교해 이전 집결에서 움직이지 않도록 합니다.

## 크기·체력바·정렬

선체 확대는 Visual의 Local Scale부터 조절하고, 물살은 Presentation, 체력바는 WorldUI에서 따로 맞춥니다. 모든 보조 요소가 Visual 안에 있다고 가정하지 마세요. 실제 자식 계층을 확인해야 합니다. Visual 내부에 있는 발사점은 확대 영향을 받고 외부 기준점은 받지 않습니다.

Sorting Order를 올리는 것은 위치 이동과 다릅니다. 탄·물기둥·경고 표시는 자체 Sorting 설정과 Y 기반 보정을 사용하므로 겹침 문제를 선체 위치만으로 해결하지 마세요. 스케일을 바꿨는데 실행 시 돌아오면 Animation 창의 Scale 트랙을 확인합니다.

## 확장 범위

적 12칸은 StageEnemyLayout의 ColumnCount=3, RowCount=4로 정해져 있습니다. 아군은 PlayerFleetLoadout의 3×3 격자에서 본함 칸을 제외한 8칸입니다. Inspector 배열 길이만 늘려 5행·4열로 바꾸는 기능은 없습니다. 확장하려면 데이터 크기, 스폰 배열, 제작 UI, 타겟/보호 규칙, 테스트를 함께 수정해야 합니다.
