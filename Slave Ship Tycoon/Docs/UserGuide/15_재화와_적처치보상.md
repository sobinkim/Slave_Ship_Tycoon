# 재화와 적 처치 보상

CurrencyManager는 재화 잔액과 차감/추가를 관리하고, RewardManager는 현재 챕터와 적의 RewardType을 이용해 처치 보상을 지급합니다. 판매 정산은 SalesManager가 별도로 계산한 뒤 재화 추가 이벤트로 연결합니다.

## 초기 재화 설정

씬 CurrencyManager의 Initial Currencies에서 Gold/Diamond/Emerald 종류와 시작 양을 정합니다. 현재 잔액은 실행 상태이므로 Inspector 초기값 변경과 구분하세요. 재화 총량은 long으로 관리하고 HUD의 K/M 같은 축약 표시는 CurrencyTextFormatter가 담당합니다.

모집 가격은 EscortGachaManager, 강화 가격은 ShipUpgradeManager에 있습니다. HUD에 적힌 가격을 바꿔 실제 소모량을 바꾸는 구조는 아닙니다.

## 새 챕터 보상 만들기

1. `Create > SB > Reward > Chapter Reward Table`로 에셋을 만들거나 기존 `Assets/SB/SO/Reward` 테이블을 복제합니다.
2. Chapter와 Route Type을 실제 ChapterContainer와 맞춥니다.
3. Enemy Rewards에 사용할 Reward Type과 재화 범위를 넣습니다.
4. Currency Type, Min Amount, Max Amount를 설정합니다.
5. 씬 RewardManager의 Reward Tables 배열에 연결합니다.
6. 적 프리팹 EnemyRewardDropCompo의 Reward Type을 해당 항목과 맞춥니다.

보상 테이블은 챕터 번호와 경로 둘 다 일치해야 선택됩니다. 일반 적과 보스의 구분도 적 RewardType과 테이블 항목으로 명시합니다. 이름이나 큰 스프라이트가 보스 보상을 자동 선택하지 않습니다.

## 범위 예시

Gold Min=10, Max=20이면 양 끝을 포함해 10~20을 추첨합니다. Min=Max=15면 고정 15입니다. 데이터는 정상 범위로 입력하고 극단적인 int 상한 등은 사용하지 마세요. 지급 재화 총량이 long이어도 이 개별 처치 추첨 범위는 int입니다.

## 표시와 지급의 차이

RewardManager는 CurrencyManager에 실제 보상을 추가하고 별도로 금화 플로팅 표시를 요청합니다. 화면에 금화 텍스트가 안 보여도 잔액은 증가할 수 있습니다. FloatingTextManager의 View Datas, Gold 프리팹, Target Canvas/Text Root/World Camera를 확인하세요.

CurrencyHudPresenter/SlotView는 잔액을, CurrencyGainLogController/ItemView는 획득 내역 표시를 담당합니다. 같은 지급을 표시하기 위해 CurrencyManager를 다시 호출하면 중복 지급이 됩니다. 화면은 이벤트/결과를 읽게 연결하세요.

## 새 재화 추가

CurrencyType enum, 초기 잔액, HUD 슬롯·아이콘·포맷, 획득 로그, 보상 테이블, 구매 비용, 정산 View를 함께 확인해야 합니다. enum 이름만 추가하고 모든 화면에서 자동 표시될 것으로 가정하지 마세요.

## 확인 순서

시작 재화 → 적 1척 처치 전후 잔액 → 모집/강화 차감 → 운송 정산 → HUD 축약 표기를 비교합니다. 보상이 없으면 콘솔의 Reward table/data not found 로그, 챕터/경로, 적 RewardType, CurrencyManager 참조를 확인합니다.
