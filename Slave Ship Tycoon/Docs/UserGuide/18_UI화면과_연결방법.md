# UI 화면 구조와 연결 방법

## 읽는 방법

View는 그림·텍스트·버튼을, Controller/Presenter는 게임 상태와 화면의 연결을 담당합니다. 보유량/가격/전투 판정은 Manager에 있습니다. 화면 변경은 View와 RectTransform부터, 규칙 변경은 Manager/데이터부터 확인하세요.

| 화면 | 연결 담당 | 표시 담당 |
|---|---|---|
| 강화 | MainShipUpgradePresenter | MainShipUpgradeView/SlotView |
| 화물 | CagoController/ItemBarManager | CagoButtonView/ItemBarView/ItemElementView |
| 함대 | PlayerFleetPanelController | PlayerFleetPanelView/FormationSlot/InventoryItem |
| 모집 | ShipRecruitmentView가 모집 흐름도 연결 | 모집 카드·결과 표시 |
| 합성 | FleetMergeScreen | FleetMergeResultView/재료 카드 |
| 지휘 | CommanderSkillBarController, GaugeSliderController | BarView/SlotView/GaugeSliderView |
| 운송 장비 | TransportEquipmentPanelController | PanelView/ItemButtonView |
| 항로 정보 | StageInfoBarController | StageInfoBarView/StageProgressGraphic |
| 판매 결과 | SaleSettlementController | SaleSettlementView/RewardSlotView |
| 재화 HUD | CurrencyHudPresenter/GainLogController | SlotView/GainLogItemView |

## 공통 패널 연결

PannelManager의 Panel Info에 Panel Type과 PanelView를 연결합니다. PanelView에는 Panel과 Button을 넣습니다. 실제 코드가 버튼에 리스너를 등록하는 경우, Button.OnClick에 같은 처리를 또 연결하면 중복 실행됩니다.

참조를 바꿀 때 해당 Controller/View의 OnEnable/OnDisable 또는 Start에서 버튼을 연결하는지 확인하세요. UnityEvent에 직접 연결된 것과 코드에서 연결한 것을 구분합니다. 새 버튼을 만들면 기존 버튼의 Inspector와 연결 방식을 출발점으로 삼는 것이 좋습니다.

## 카드 크기·행렬 조절

보유함 카드는 `Assets/SB/Prefabs/UI/EscortInventoryItem.prefab` 및 격자용 프리팹을 확인합니다. 카드 개별 아이콘/텍스트/색은 EscortInventoryItemView의 참조를, 배치 간격·열 수는 부모 GridLayoutGroup을 조절합니다.

같은 종류는 카드 한 개와 수량으로 표시합니다. 카드 수가 보유 척 수와 같지 않은 것이 정상입니다. 함대 6칸 수는 UI 격자의 Column Count만 변경해 늘릴 수 없습니다. 편성 데이터·스폰 구조를 함께 바꿔야 합니다.

FleetAttackPreview는 선택한 프리팹의 TargetSelector를 읽어 전열/중열/후열 우선순위와 고체력 모드를 설명합니다. 문구만 바꾸지 말고 실제 규칙과 일치시키세요.

## 화면 애니메이션

PanelFadeIn의 Duration Seconds로 함대/합성 페이드를, ShipRecruitmentView의 Reveal Seconds/Card Delay Seconds/Initial Scale로 모집 공개를, SaleSettlementView의 Reward Count Seconds/Reward Row Delay Seconds/Entry Scale로 정산 연출을 조절합니다.

화면을 열 때 전투가 정지되는 경우 UI는 unscaled 시간을 사용해야 진행됩니다. 함대 화면은 FleetScreenPause가 이전 시간 배율을 복원합니다. 합성→함대→게임으로 돌아갈 때 배율이 정상인지 확인합니다.

## 항로·결과·페이드

StageInfoBarController의 타이틀/설명 필드에서 해적/운송/보스 문구를 바꿉니다. StageProgressGraphic은 단계 수에 맞춰 진행 표시를 그리며 Diameter/Spacing/Ring Width/정렬 관련 필드로 모양을 조절합니다. StageResultPopupController/View는 승패와 챕터 진입 문구·페이드/유지시간을 연결합니다.

ScreenFadePanelControler/View는 화면 전환 페이드를 담당합니다. 현재 파일명 Controler를 검색에 사용하세요. 시각 효과를 재생하는 것과 다음 챕터를 실제로 진행시키는 이벤트는 서로 연결되어 있으므로 팝업 루트를 통째로 삭제하기 전에 수신 흐름을 확인합니다.

## 한글 폰트

TMP Text의 Font Asset과 Fallback을 확인합니다. `Assets/SB/Fonts/MalgunGothic SDF.asset`, `SummonKorean SDF.asset` 등 기존 에셋을 참고하되 실제 텍스트 오브젝트에 연결된 폰트를 확인하세요. 새 글자가 네모이면 글리프 포함 여부, Dynamic/Fallback, 콘솔 경고를 확인합니다.

## 조절 뒤 확인

1080×1920 같은 기준 세로 화면 외에도 좁은/긴 비율에서 잘림을 봅니다. Canvas Scaler, Anchors, Layout Group, Content Size Fitter를 함께 확인하고, 부모 레이아웃이 자식 크기를 덮어쓰는지 확인하세요. 노치·Safe Area·실기기 터치는 별도 검증 항목입니다.

UI Setup 도구는 기존 모양을 다시 적용해 커스텀을 덮을 수 있습니다. 일상 편집은 Inspector와 프리팹을 사용하고 [20번 도구 안내](20_에디터도구와_검증방법.md)를 먼저 읽으세요.
