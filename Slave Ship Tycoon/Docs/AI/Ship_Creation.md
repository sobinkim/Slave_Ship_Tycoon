# 플레이어 호위선 제작 규칙

새 플레이어 호위선 종류를 만들거나 기존 함선 프리팹·데이터·모집 등록을 바꿀 때만 읽습니다.

## 먼저 확인할 자료와 실제 상태

- 상세 조립 절차와 필드 표: [02_아군함선_양산과_등록.md](../UserGuide/02_아군함선_양산과_등록.md)
- 본선(운송선) 제작은 호위함과 별도입니다. 관련 요청일 때만 `Assets/SB/Docs/TransportMainShip.md`를 읽습니다.
- 깃발·돛 움직임이나 함선 그림·머티리얼을 바꿀 때만 [ShipClothFlutter.md](../ShipClothFlutter.md)를 읽습니다. 천 영역과 스프라이트 좌표 설정이 그림에 연결되어 있습니다.
- Unity MCP로 원본 프리팹, 함선 데이터, 카탈로그, 가챠 테이블과 실제 씬 편성/스폰 경로를 먼저 확인합니다. 문서의 경로와 현재 에셋이 다르면 실제 에셋을 기준으로 수정하고 문서 차이를 보고합니다.

## 호위선 추가 흐름

새 종류가 필요하면 프리팹, `EscortShipData`, 카탈로그 등록을 확인합니다. 모집으로 획득하게 할 때만 가챠 테이블에도 추가합니다. 프리팹 복제만으로는 카탈로그나 모집에 자동 등록되지 않습니다.

1. 비슷한 역할의 기존 프리팹을 기준으로 복제할지 Prefab Variant로 이어갈지 결정합니다. 독립 변경은 일반 복제, 원본 업데이트를 계속 상속할 이유가 명확할 때는 Variant를 사용합니다.
2. Ship Type, Entity Name, Ship Role, 시각 자산, Animator/클립, 공격·표적 선택·체력·피격 참조를 점검합니다. 역할 enum만으로 방어·공격 특수 능력이 생긴다고 가정하지 말고 실제 동작 컴포넌트를 확인합니다.
3. 함선별 기획 수치와 조절값은 기존 데이터/Inspector 구조를 따릅니다. 공유 ScriptableObject를 수정하면 다른 함선에도 영향이 가는지 먼저 확인합니다.
4. `EscortShipData`에 종류마다 고유한 Stable Id, 표시 이름, 아이콘, 등급, 프리팹을 연결합니다. 복제한 데이터의 ID를 그대로 두지 않습니다.
5. 카탈로그에 등록합니다. 기존 순서를 임의로 정렬하지 않습니다. 합성 결과가 카탈로그 순서에 의존하므로 다음 등급 선택을 검토합니다.
6. 모집이 요구될 때만 가챠 테이블에 한 번 등록하고 Weight를 지정합니다. 확률은 해당 항목 Weight를 전체 Weight 합으로 나눈 값으로 검토합니다.
7. 초기 지급/초기 편성이 요청된 경우에만 해당 씬 데이터에 명시적으로 추가합니다.

## 확인

- 프리팹 모드에서 참조가 새 프리팹 내부를 가리키는지 확인합니다. 공유 Animator Controller/클립을 수정하면 원본 외형도 달라질 수 있습니다.
- 단독 편성 후 대기·이동·공격·피격·사망, 스테이지 재출항 후 복원, 카드 아이콘·모집 획득·편성 교체를 확인합니다.
- 특수 효과를 제공하는 함선은 복제본에 의도하지 않은 제공 컴포넌트/참조가 남지 않았는지 확인합니다.
- 안정 ID 중복, 누락된 프리팹/아이콘, 카탈로그 등급 순서, 가챠 중복 항목을 검증하고 결과를 보고합니다.
