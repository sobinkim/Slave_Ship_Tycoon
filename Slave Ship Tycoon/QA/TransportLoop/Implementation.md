# 운송 루프 개선 구현 기록

2026-10-13 기준. 운송의 가치 상승과 봉쇄선 돌파, 정산 후 성장, 정비 후 재개가 이어지도록 구현했습니다. 후속 축소 HUD 및 긴장감·배경 제거 조정까지 포함한 현재 상태이며, 아래 앞선 검증 완료 범위와 최신 연출 QA 진행 중 항목을 구분합니다.

## 구현

- **시세 공개:** 화물별 순차 공개를 구간당 동시 공개로 변경했습니다. 최신 일반 총시간은 1.6초, 특별은 2.2초이며 이전 0.9/1.6초를 대체합니다. 특별 결과는 목표 재화 증가액/기본 가치 30배 이상, 운송당 최대 1회로 제한해 강조의 차이를 줍니다. 실제 확률·보상 규칙은 유지합니다.
- **결과를 기다리는 순간:** 일반·특별 상승 모두 링 응축·흔들림 0.6초 → 정지 0.1초 → 배율 pop·별빛 → coin stream 순서입니다. 공개 전 공개 대상 배율을 `× ?`로 가리고 중립 문구를 사용하며 재화 결과 행을 숨깁니다. 첫 실제 coin stream 도착부터 예상액 카운트와 목표 숫자·아이콘 punch를 시작합니다.
- **작은 운송 HUD:** 1080×1920에서 평상시 높이 실측 126px입니다. 화물 타일은 56px, 그림은 50px로 두고 시세 공개 중에만 92px/82px로 확대합니다. 종료 시 0.18초 동안 축소합니다. 중복된 세 재화 예상액과 상세 문구는 숨기고 목표 재화의 도착 예상액을 표시하며 재화 stream을 목표 아이콘으로 보냅니다.
- **아이콘 뒤 배경 제거:** 타일의 상태별 사각 배경과 사각 flash VisualElement를 삭제했습니다. 공개 영역도 투명하게 두고 외곽선 글자·링·별빛으로 강조하며 기존 그림 에셋은 유지합니다.
- **출항 목표와 정확한 가치:** 한 통화 정산 효과가 있는 출항 장비는 그 통화를 목표로 저장합니다. 그 외에는 Inspector 기본 목표를 사용합니다. 기본 화물 가치 + 누적 시세 보너스 + 출항 장비 기여는 동일 snapshot을 사용합니다. 도착 전 금액은 예상액입니다.
- **봉쇄선과 정산:** 마지막 구간 제목을 `마지막 봉쇄선`으로 표시합니다. 정산에서는 운송 완주·하역 완료와 최종 지급액을 강조하고 기존 세 재화 카운트 뒤 지급 완료를 표시합니다. 정산 목표와 분해를 이벤트 시점에 저장해 재생해도 유지하며, 실제 지급 합계와 맞지 않는 분해는 숨깁니다. 정산 카드 높이는 최신 조정에서 74%입니다.
- **성장 연결:** 정산의 `함대 강화`와 `호위선 모집`은 기존 성장 화면으로 연결합니다. 새 유지 시간 기본값은 6초이며 기존 유지 시간과 더 긴 값을 사용합니다. 자동 진행·닫기, 실제 지급 이벤트와 전환 완료 이벤트의 단일 경로는 유지합니다.
- **정비 후 재개:** `파밍 복귀`는 현재 운송 구간을 저장하고 이전 파밍 해역으로 돌아갑니다. 이후 `운송 재개`로 같은 구간에서 이어갑니다. 화물·시세·출항 장비를 보존하고 출항·정산을 중복 실행하지 않습니다. 정박 중 다른 보스 출항, 챕터 전환 중 복귀·재개는 차단합니다.
- **첫 항로 편성:** Chapter 2 첫 구간은 적 6척→3척입니다. 마지막 구간의 일반 포격함 한 척을 기존 회복 지원함으로 교체했습니다. 이전 두 에셋은 [Before](Before/)에 보관합니다.

## 확인한 범위

- 최신 연출 코드는 컴파일에 성공했습니다. 자연 운송의 미공개 단계에서 `× ?`, 기존 예상액 유지, 네 타일 배경 alpha 0을 확인했습니다. 최신 일반 연출을 복사한 UI 시세 snapshot으로 29프레임 기록했고 원본 MarketPriceManager 값이 변하지 않았습니다. [움직임 미리보기](../../Assets/QA/TransportLoop/10-anticipation-preview.gif)와 [프레임 기록](anticipation-timing.tsv)을 남겼습니다.
- 프레임 기록에서 0.640초까지 결과를 가리고 0.711초에 공개했습니다. 예상액은 재화가 비행 중인 0.926초까지 유지되고 0.999초 표본부터 증가했습니다. 1.281초에는 카운트가 완료됐고 1.636초에 확대 상태가 해제됐습니다. 다음 항목은 이전 버전에서 확인한 운송·정산·복귀 회귀 검증입니다.
- 자동 검사 **4개 통과**: 정확한 운송 구간 저장, 출항 snapshot을 초기화하지 않는 동일 구간 재개, 정박 중 다른 보스 출항 차단, 챕터 전환 중 복귀·재개 차단입니다. 검사에서는 정박·재개가 화물 변경/출항/정산 이벤트를 발생시키지 않는지도 확인합니다.
- 실제 **전체 운송→정산 1회**를 확인했습니다. 이 기록은 이후 최신 화면 수정까지 모두 다시 완주했다는 의미는 아닙니다.
- 최신 평상시 축소 HUD의 126px 높이와 [캡처](../../Assets/QA/TransportLoop/04-transport-compact.png)를 확인했습니다. [시세 상승 연출](../../Assets/QA/TransportLoop/05-transport-bonus.png) 중 확대, 종료 후 축소도 실제 운송에서 확인했습니다. 감소·변동 없음에서는 화물을 확대하지 않습니다.
- 실제 버튼으로 운송 4-2→파밍→4-2 재개를 확인했습니다. 버튼이 `운송 재개`로 바뀌고 재개 전후 모든 화물 배율이 같았습니다. [재개 후 축소 상태](../../Assets/QA/TransportLoop/06-transport-resumed-compact.png)에서 높이도 126px로 복원됐습니다.
- [74% 정산 카드](../../Assets/QA/TransportLoop/07-settlement-growth.png)에서 모든 금액과 성장 버튼을 확인했습니다. 강화 버튼은 Upgrade 패널로, 모집 버튼은 활성 RecruitmentScreen으로 연결되며 정산 창이 닫혔습니다.
- 동일 구간 실패 이벤트를 두 번 발행한 런타임 검사에서 배율은 `8/5/8/15 → 6/4/6/12 → 6/4/6/12`였습니다. 기본 x1 이상을 보존하고 같은 구간에서 중복 차감하지 않았습니다.
- 게임 실행에서 기존 `MerchantLedger needs an icon.` 장비 아이콘 누락을 관측했습니다. QA 프레임 캡처의 초기 ScreenCapture 시도에서는 프레임 종료 시점 오류가 발생했습니다. 이후 Unity Pipeline의 GameView 렌더 타깃 캡처로 교체해 정상 기록했으며, 해당 오류는 임시 QA 평가 코드에서 발생한 것으로 게임 소스 변경 오류와 구분합니다.

## 미확인

- 최신 특별 결과의 2.2초 전체 연출은 일반 결과의 프레임 기록과 별도로 다시 녹화하지 않았습니다.
- 장비 snapshot 효과의 일반 계산은 정적 검토와 자동 검사로 확인했습니다. 현재 씬의 MerchantLedger 아이콘 누락으로 해당 장비를 장착한 실제 항해 검증은 하지 못했습니다.
- 다른 화면 비율, Safe Area, 실제 모바일 터치는 미검증입니다.
- QA 종료 후 Play Mode를 정지하고 Time.timeScale=1로 복원했습니다. Editor는 Canvas만 dirty로 표시했습니다. 미저장 변경 유실 위험으로 자동 승인 검토가 씬 재열기를 거절하여, 해당 미저장 상태를 보존했습니다. 요청한 연출 소스와 두 시간의 씬 설정은 QA 시작 전에 저장되어 있습니다.

게임 규칙과 화면 연결의 최신 안내는 [UI_InGame_Cargo.md](../../Docs/AI/UI_InGame_Cargo.md)를 참고합니다.
