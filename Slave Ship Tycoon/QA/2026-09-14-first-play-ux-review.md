# 첫 플레이 기준 UX·피드백 QA

검토일: 2026-09-14  
대상: Unity 6000.0.59f2, `Assets/SB/Animations/Scenes/SampleScene.unity`, Game View 1080×1920  
관점: 규칙을 모르는 신규 플레이어가 화면에서 얻는 정보만으로 다음 행동과 결과를 이해할 수 있는가.

## 핵심 판단

자동 전투와 재화 획득, 강화, 모집, 합성이라는 기능의 연결은 확인했다. 가장 큰 부족함은 **선택하기 전의 판단 정보와 선택한 뒤의 효과 확인**이다. 버튼은 있지만 무엇을 위해 눌러야 하는지, 눌렀더니 얼마나 좋아졌는지가 약하다.

특히 화물과 운송 장비는 게임의 차별점인데, 현재 화면에서는 일반적인 부가 메뉴처럼 보인다. 전투 장면에 이펙트를 더하는 것과 함께, 이 두 메뉴가 보상의 종류와 크기를 결정한다는 사실을 먼저 전달할 필요가 있다.

## 범위와 해석 기준

- 첫 화면·함대·모집은 기획서를 읽기 전에 살펴보고 첫 인상을 기록했다. 이후 기획서를 읽되, 기획 지식을 신규 플레이어의 지식으로 취급하지 않았다.
- Play Mode에서 일반 파밍, 화물 1회 적재, 공격력 1회 강화, 보스 진입, 운송 2-1~2-5와 다음 파밍 진입, 1회 모집, 미편성 함선 3척 합성을 확인했다.
- 상호작용은 Unity의 기존 Button 이벤트 및 PointerDown/Up 처리기를 호출했다. 실제 손가락 터치, 레이캐스트 차단, 터치 영역과 오조작률까지 검증한 것은 아니다.
- 사용자 설명에 따라 **Space 시작은 테스트 전용 동작으로 제외**했다. 테스트 수치·임시 그림·미완성 콘텐츠는 출시 결함으로 단정하지 않았다.
- 정산은 지급 후 남아 있는 UI 텍스트와 구현을 확인했다. 정산 애니메이션 전 과정을 연속 관찰하지 못했으므로 타이밍 체감 평가는 보류한다.
- 짧은 시점별 화면 캡처로 확인했다. 사운드를 직접 청취하거나 녹화 영상을 프레임별 분석하지 않았다.
- 코드·씬·프리팹 수정 없이 QA했다. QA에서 시작한 Play Mode는 종료했다. 종료 시 컴파일 실패 및 콘솔 오류·경고는 0이었다.

## 우선 고칠 UX

우선순위 A는 핵심 선택·목표 이해를 막는 항목, B는 조작과 성장 체감을 약하게 하는 항목이다. 시간·인원 추정치는 아니다.

### A1. 화물은 무게만으로 고르게 되어 있다

**관찰:** 화물 두 줄에 같은 배 그림, `무게 20`, `무게 24`, ± 버튼만 표시된다. 이름·현재 수량·기본 가치·정산 재화가 각 행에 함께 나오지 않는다. +를 누르면 전체 적재량이 `0/300 → 20/300`으로 바뀐다.

**초보자 반응:** “둘 중 무엇이 더 좋은가? +를 누르면 돈을 쓰나? 왜 이걸 싣지?” 무게가 낮은 것을 고르는 것이 유리한지조차 판단하기 어렵다.

**수정 제안:** 각 행을 `화물명 / 보유 또는 적재 수량 / 개당 무게 / 기본 정산 보상`으로 구성한다. 버튼은 `싣기`, `내리기` 또는 같은 의미의 명확한 보조 문구를 붙인다. 적재 직후에는 총 무게뿐 아니라 예상 보상 변화도 보여준다. 실제 비용이 있다면 누르기 전에 표시한다.

**검증 기준:** 설명 없이 두 화물의 차이와 자신이 하나를 선택한 이유를 말할 수 있어야 한다.

근거: [화물 화면](../Assets/QA/2026-09-14/08-cargo.png)

### A2. ‘장비’가 전투 장비처럼 읽히고, 운송 중 적용 시점이 불명확하다

**관찰:** 하단 탭은 `장비`, 화면 제목은 `운송 장비`다. `상인 장부 — 골드 x1.5`, `지휘 명령서 — 에메랄드 +300` 등 효과는 보인다. 하지만 다음 운송에 적용되는지, 이미 진행 중인 운송에도 적용되는지는 화면에서 설명하지 않는다.

**초보자 반응:** “함선 공격력을 올리는 장비인가? 지금 바꾸면 이번 보상이 바뀌나?” 보상 방향을 고르는 중요한 메뉴라는 사실을 놓치기 쉽다.

**수정 제안:** 탭을 `운송품` 또는 `운송 장비`로 명명하고 `목적지 정산 보상을 바꿉니다`를 붙인다. 운송 시작 시 설정을 고정하는 실제 규칙에 맞춰 `이번 운송 적용: 상인 장부 / 변경 장비는 다음 운송부터`처럼 표시한다. 화물 화면에도 적용 중인 장비와 보상 효과를 연결해 보여준다.

**검증 기준:** 운송 도중 장비를 바꾼 플레이어가 이번 정산 결과를 잘못 예상하지 않아야 한다.

근거: [장비 화면](../Assets/QA/2026-09-14/09-equipment.png), `TransportEquipmentManager`의 운송 스냅샷을 사용하는 `SalesManager` 정산 경로.

### A3. 강화의 대상과 상승량을 알 수 없다

**관찰:** 강화 카드에는 이름, 레벨, 가격이 있다. 공격력 입력 후 `Lv. 0 → Lv. 1`, 가격 `120 → 140`은 확인된다. 실제 공격력 증가량이나 적용 대상은 나오지 않는다. 화면 제목은 `함선 강화`지만 기획에서는 공격력·공속이 함대 전체에 적용된다.

**초보자 반응:** “본선만 강해졌나? 전부 강해졌나? 운은 뽑기 확률인가?” 레벨이 오르는 것은 알아도 구매 판단과 성장 확인이 어렵다.

**수정 제안:** `함대 공격력`, `본선 체력`처럼 대상이 드러나는 이름을 쓴다. 현재값과 다음값을 `현재 → 다음`으로 표시한다. 운에는 `운송 시세 상승에 영향` 등 실제 효과를 명시한다. 강화 후 증가 수치를 짧게 강조한다.

**검증 기준:** 강화한 플레이어가 적용 대상과 바뀐 능력치를 바로 설명할 수 있어야 한다.

근거: [강화·전투 화면](../Assets/QA/2026-09-14/07-battle.png), `MainShipUpgradeSlotView.Refresh`와 실제 입력 결과.

### A4. 재화가 서로 다른 용도를 가진다는 사실이 HUD에서 끊긴다

**관찰:** HUD는 이름 없는 아이콘 3개와 숫자를 표시한다. 모집에서는 `다이아`, 장비에서는 `에메랄드`, 전투에서는 `지휘력`이 등장한다. 강화 가격에도 재화 종류 표시가 없다.

**초보자 반응:** “초록 재화가 지휘 게이지인가? 지휘력과 지휘 강화 재화는 같은 것인가?” 같은 모양의 배 아이콘에 색만 달라 학습 부담이 커진다.

**수정 제안:** HUD에 짧은 이름 또는 탭 설명을 제공한다. 가격 옆에는 지불 재화 아이콘을 반드시 붙인다. 지휘 게이지와 영구 강화에 쓰는 지휘 재화는 이름·아이콘·설명에서 구분한다. 기획 용어와 게임 표시 용어를 대응시켜 통일한다.

**검증 기준:** 강화·모집 전에 어떤 재화가 줄어들지 맞힐 수 있어야 한다.

### B1. 모집과 합성 이후 ‘써먹는 단계’가 빠져 있다

**관찰:** 모집 결과에 `보유 함대에 추가되었습니다`가 표시되고, 합성 결과에 `정예 호위선 획득!`과 결과 등급이 나온다. 함대 화면에는 비어 있는 4번 슬롯이 있었지만 결과 화면에는 편성으로 이어지는 행동이 없다. 성능 비교도 없다.

**초보자 반응:** “얻었으니 전투에도 자동으로 들어갔겠지?” 보유 수 증가가 실제 전투력 증가라고 오해할 수 있다.

**수정 제안:** 결과에 `보유함에 추가 · 미편성` 상태를 표시하고 `함대에서 편성` 이동 버튼을 둔다. 빈 슬롯이 있으면 위치를 알려준다. 기존 함선 대비 역할·핵심 스탯을 보여주되 자동 편성은 별도로 결정할 기능이다.

**검증 기준:** 처음 뽑은 함선을 도움 없이 편성하고 전투에서 확인할 수 있어야 한다.

근거: [모집 결과](../Assets/QA/2026-09-14/06-recruit-result.png), [합성 결과](../Assets/QA/2026-09-14/14-merge-result.png)

### B2. 함대 편성에서 위치와 함선 선택의 근거가 약하다

**관찰:** 1~6 슬롯과 선택 후 배치하라는 안내는 명확하다. 반면 카드에는 이름·등급·보유 수 중심의 정보만 있어 공격 방식, 생존력, 슬롯의 전열·후열 의미를 파악하기 어렵다.

**수정 제안:** 슬롯에 전열·후열 또는 실제 전투 위치를 대응시키는 작은 배치도를 제공한다. 함선 카드에 역할 한 줄과 공격력·공격 간격 같은 핵심 수치만 먼저 보여준다. 교체 전에 현재 함선과 비교할 수 있게 한다.

**검증 기준:** 플레이어가 임의 배치가 아니라 역할이나 위치를 근거로 한 번 이상 편성을 바꿀 수 있어야 한다.

근거: [함대 화면](../Assets/QA/2026-09-14/03-fleet.png)

### B3. 누를 수 없는 이유와 버튼의 상태가 일관되게 전달되지 않는다

**관찰:** 합성 재료 선택 시 다른 등급 카드는 `선택 불가`로 바뀐다. 이유는 표시하지 않는다. 재료 0개인 합성 버튼도 청록색으로 강하게 보여 준비 완료와 혼동할 여지가 있다. 메인에서는 선택된 `강화`와 `모집` 버튼이 모두 청록 계열이다. 강화·화물 길게 누르기는 코드에 존재하지만 화면 안내는 없다.

**수정 제안:** `등급이 다름`, `미편성 함선 부족`, `최고 등급`처럼 원인을 구체화한다. 선택 탭·주요 행동·사용 불가를 서로 다른 시각 규칙으로 표현한다. 강화·적재에 `길게 눌러 연속`을 짧게 안내한다.

**검증 기준:** 불가능한 버튼을 반복해서 누르지 않고 이유를 이해하며, 연속 입력을 발견할 수 있어야 한다.

## 연출 평가

### 유지할 점

- 바다 배경, 좌우 대치, 포구 섬광과 포탄으로 자동 함대전이라는 상황이 읽힌다.
- 함선 아래 물결 효과가 배가 수면 위에 있다는 인상을 보탠다.
- 격파 금액과 재화 HUD 증가가 있어 반복 파밍이 진행된다는 신호는 있다.
- 모집의 비용 표시, 합성의 `3/3` 및 결과 등급 예고는 결과를 예상하게 해주는 좋은 요소다.

### 추가로 보완할 점

1. **보상 로그와 본선이 겹친다.** 좌측 획득 로그가 본선 위에 쌓여 함선 상태를 가린다. 획득 메시지는 재화 HUD 가까이 별도 영역에 두고, 전투 공간에는 피해와 중요한 전투 상태를 우선한다. 근거: 전투 화면 07·08·11.
2. **피해 숫자만으로 생존 위험을 읽기 어렵다.** 관찰 화면에서는 지속적인 본선 체력 표시를 확인하지 못했다. 최소한 본선 체력과 위험 상태를 명확히 표시하고, 호위선 상태는 피격·선택 시 보조 표시하는 식으로 정보량을 조절한다. 패배 장면까지 관찰하지 못했으므로 저체력 연출의 부재 자체는 단정하지 않는다.
3. **1회 모집 결과의 시선 중심이 약하다.** 결과 카드가 넓은 화면의 좌상단에 작게 놓이고 빈 공간이 많다. 1회 결과는 중앙에서 크게, 다회 결과는 격자로 분리한다. 멋진 전면 문구보다 얻은 함선·등급·활용처를 먼저 보이게 한다.
4. **합성은 성공했지만 변화가 작게 느껴진다.** 재료가 비워지고 작은 결과 이미지와 문장으로 완료된다. 재료 3척이 1척으로 모이는 짧은 전환과 결과 등급·성능 상승을 강조하면 성공을 놓치지 않는다. 반복 합성을 막는 긴 연출은 피한다.
5. **사운드는 별도 확인이 필요하다.** 조회 시 활성 AudioSource는 0개였다. 직접 청취하지 않았으므로 무음이라고 확정하지 않는다. 포격·피격·격침·강화·희귀 획득·정산의 구별 여부를 후속 청취 QA 대상으로 둔다.

동일 함선 그림, `일반`인데 이름은 `전설 호위선`, 모집의 `레어`와 함대의 `희귀` 차이는 관찰했다. 임시 테스트 데이터일 수 있으므로 우선 결함에서는 제외하되, 콘텐츠 교체 시 명칭·등급·역할을 함께 정리해야 한다.

## 기획서에 이미 있어 새 제안으로 중복하지 않는 항목

아래는 중요하지만 기획서에 이미 방향이 있다. 신규 아이디어가 아니라 구현 후 확인할 항목이다.

| 기존 기획 | 현재 확인 | QA에서 확인할 기준 |
|---|---|---|
| 운송 진행도·시세·예상 판매액 상시 표시 | 운송 2-5 상태에서도 상단은 `스테이지`와 작은 화물 수량·배율 위주 | 몇 전투가 남고 얼마를 받을지 설명할 수 있는가 |
| 스킬 타겟 데칼·불 포탄·나팔 등 명령별 피드백 | 이번 QA는 수동 스킬 발동 연출까지 충분히 관찰하지 않음 | 무엇이 누구에게 언제 적용됐는가 |
| 홀수 웨이브 연결과 첫 포격 템포 | 반복 파밍은 동작. 로그상 표본 웨이브 시작 간격은 약 2.8~5.5초 | 강화·메뉴 조작 중에도 흐름이 끊기는 느낌이 적은가 |
| 대정산과 강화 전후 성장 체감 | 2장 정산 후 UI 데이터에 `화물 1 / 최고 x134 / 골드 +201M` 기록 | 지급 이유와 강화에 쓸 수 있는 양을 이해하는가 |
| 홀드 강화와 대량 구매 | 홀드는 구현되어 있음. 안내가 보이지 않음 | 기능이 이미 있더라도 초보자가 발견하는가 |
| 운송 실패 시 원금 보존·복귀 수단 | 이번 실행에서 패배를 재현하지 않음 | 무엇을 잃고 무엇이 보존됐는지, 어떻게 복구할지 보이는가 |

정산 화면은 연결되어 있으며 참조 누락이 아니다. 중간 조사에서 직렬화 출력의 instanceID 표기를 누락으로 잘못 해석했으나 실제 객체 참조 확인으로 정정했다. 정산 개선의 근거는 표시 내용과 구현이다. `SaleSettlementView`는 기본 0.3초 등장·2.5초 유지·0.35초 퇴장 구조이고, 요약에는 총 화물과 최고 배율을 표시한다. 최종 금액의 원금·시세·장비 기여를 나눠 확인하는 기능과 지난 정산 재확인 수단은 별도 검토할 가치가 있다.

## 다음 QA의 확인 범위

- 수동 지휘 명령과 자동 사용을 각각 발동해 효과·대상·지속시간·실패 이유를 확인한다.
- 함대가 실제 패배하는 난도로 본선 위험 표시와 패배 후 복구 안내를 확인한다.
- 운송 중 장비 변경·화물 변경이 이번 정산과 다음 정산에 어떻게 반영되는지 비교한다.
- 실제 기기 터치로 길게 누르기, 버튼 겹침, 뒤 화면 입력 차단, 화면비·안전 영역을 확인한다.
- 정산 연출을 연속 녹화해 정보가 읽히는 시간과 다음 전투·팝업의 겹침을 확인한다.
- 신규 플레이어에게 설명 없이 `원하는 보상 준비 → 운송 → 정산 → 강화 → 새 함선 편성`을 시키고, 막힌 지점과 오해를 기록한다.

추천 수정 순서는 **화물·운송 장비의 선택 정보 → 강화·재화의 효과 정보 → 모집/합성에서 편성으로 연결 → 전투 정보 겹침과 결과 강조**다. 기존 기획의 운송 HUD는 이 작업과 함께 적용해야 핵심 루프가 읽힌다.
