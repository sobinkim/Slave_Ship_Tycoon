# 프로젝트 작업 안내

이 파일은 모든 작업에 필요한 공통 규칙과 주제별 안내의 색인입니다. 매번 모든 문서를 읽지 말고, 요청과 직접 관련된 문서만 읽으세요.

## 주제별 안내

- 새 세션의 게임 플레이 스타일·전투 흐름·배치 규칙·기획 시 주의점을 파악할 때: [Docs/AI/Game_Playstyle.md](Docs/AI/Game_Playstyle.md)
- UI를 만들거나 수정하거나 기존 화면을 UI Toolkit으로 옮길 때: [Docs/AI/UI_Toolkit.md](Docs/AI/UI_Toolkit.md)
- 플레이어 호위선을 새로 만들거나 함선 프리팹·데이터·모집 등록을 바꿀 때: [Docs/AI/Ship_Creation.md](Docs/AI/Ship_Creation.md)
- 다른 주제 문서는 요청이 직접 해당할 때에만 엽니다. 예: UI 화면 연결은 `Docs/UserGuide/18_UI화면과_연결방법.md`, 함선 데이터 등록은 `Docs/UserGuide/02_아군함선_양산과_등록.md`.

## 세션 공통 기획 맥락

새 세션에서 게임 플레이를 전제로 한 기획·밸런스·QA를 시작할 때는 [Docs/AI/Game_Playstyle.md](Docs/AI/Game_Playstyle.md)를 먼저 읽고, 실제 플레이 규칙을 가정하지 않습니다. 이 문서는 대화 중 합의된 의견과 현재 코드에서 확인한 사실을 구분합니다.

매 세션 시작 시 Notion MCP의 활성 Skill을 조회합니다. 이 프로젝트에서는 `세션 공통 기획 맥락` Skill을 읽고 확정 기획, 권장 수치, 미정 항목을 구분합니다. 이미 현재 세션에서 읽었다면 다시 읽을 필요는 없습니다.

## Unity 작업 방식

1. Unity MCP를 우선 사용해 관련 씬, GameObject, 컴포넌트, 프리팹, 에셋의 실제 상태를 확인하고 Editor 경로로 수정합니다.
2. Unity CLI는 MCP로 하기 어렵거나 반복 검증이 필요할 때 사용합니다. 실행 전후로 대상과 결과를 확인합니다.
3. 코드나 YAML을 직접 수정하기 전에 구조와 참조를 확인합니다. 실행 중인 Editor가 있으면 파일 충돌을 피하고 MCP/Editor 경로를 우선합니다.
4. 기존 씬·프리팹·에셋·ProjectSettings를 명시적 요청 없이 대량 변경하거나 삭제하지 않습니다. 기존 Inspector 값과 사람이 만든 설정을 임의로 덮어쓰지 않습니다.
5. 새 패키지, 외부 의존성, 전역 설정 변경은 필요한 이유와 영향 범위를 먼저 검토합니다.

## 구현 원칙

- 요청된 범위만 작게 구현하고 기존 구조와 이름·이벤트·생명주기 관례를 따릅니다.
- AI 편의용 자동 탐색·자동 배치·자동 보정·자동 밸런싱을 요청 없이 추가하지 않습니다.
- 기획과 밸런스 값은 매직 넘버로 숨기지 말고 Inspector 필드, enum, 명시적 참조 또는 목적이 분명한 데이터 에셋으로 노출합니다.
- 사용자가 직접 연결할 프리팹·Transform·데이터는 자동 탐색보다 명시적 할당을 우선합니다.
- 각 컴포넌트는 명확한 역할을 맡고 연결·해제 시점과 상태 전환이 읽히게 합니다. 반복 요구가 확인되기 전 범용 프레임워크를 만들지 않습니다.
- 클래스/공개 멤버는 PascalCase, private 필드는 camelCase를 사용합니다. Inspector 필드는 `[SerializeField] private`로 선언하고 필요한 Tooltip/Min/Header를 붙입니다.
- `Update`에서 반복적으로 `Find`, `GetComponent`, 전체 오브젝트 탐색을 하지 않습니다. 참조를 캐시하고 코루틴·이벤트·생성 오브젝트의 해제 지점을 분명히 합니다.

## 완료 보고

변경 파일, 핵심 Inspector 조절 항목, 수행한 검증, Editor에서 남은 연결·확인 사항을 간결하게 보고합니다. 기존 오류와 새 변경으로 발생한 오류를 구분합니다.
